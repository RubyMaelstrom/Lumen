ASCII regex windows of Unicode strings — 30 September 2026
=========================================================

A prepared substring previously inherited its parent's wide subject shape even
when all visible characters were ASCII. ReText::window now compares the already
known byte length and exact UTF-16 span. Every non-ASCII scalar requires more
UTF-8 bytes than UTF-16 units, so equality proves ASCII without another scan.
Such windows select the existing byte matcher and need no parent element table
owner. Wide windows retain their mapping. LStr view layout and native string
byte-reader guards remain unchanged.

Tests compare relative captures with the full backtracker over multiple flags,
anchors, boundaries, lookarounds, named captures and start positions. Excluded
prefix/tail characters remain invisible. Wide mappings and split-surrogate
declines are checked separately. Forty regexp, 24 regex and nine string-slice
tests pass; strict engine all-target Clippy passes. No new whole-suite, x64,
wasm or Test262 result is claimed.
