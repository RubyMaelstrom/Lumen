Compact CLDR date tables — 2026-10-06

Date tables now store deduplicated UTF-8 text in one static blob and use u16
string IDs in their rows. A directory of u32 offsets and lengths replaces
repeated static string pointers. Lookup still compares string contents in the
same sorted order and returns borrowed static strings. There is no runtime
allocation, unsafe code, new dependency, or locale-data update in this change.

The generator pins CLDR JSON 48.0.0 at
4d06be52b51bb2f75688d0abe55c52a66afed790 and records 384 input hashes beside the
generated source. Before conversion, the original generator reproduced the
previous checked-in source byte for byte. An exhaustive comparison found all
32,616 month/era records unchanged across 48 tables. The compact blob contains
4,489 distinct strings in 68,955 bytes. Tests check all references for bounds,
UTF-8 boundaries and deduplication, plus lookup and fallback behavior.

The ECMA-402 FormatDateTimePattern algorithm requires the selected localized
representations and format widths to survive this storage change. Consulted
snapshot: b1c961988b9a07894b1dc3dc2b5626ea48387d61, fetched 2026-09-06;
/big/web-standards/repositories/tc39/ecma402/spec/datetimeformat.html:1342;
https://tc39.es/ecma402/#sec-formatdatetimepattern .

Startup medians were 10.063 ms and 8.253 ms. The executable shrank from
26,108,888 to 21,665,320 bytes; ELF relative relocations fell from 310,333 to
197,067. App peak RSS fell approximately 0.7% to 19.6%, depending on workload.
No component crossed the documented 3% regression gate. Separate diagnostics
showed matching compilation/collection counts and essentially unchanged
managed post-GC memory and generated code. Individual instrumented compilation
and pause times are not stable comparison distributions.
