No-match replacement — 30 September 2026
=======================================

RegExp @@replace previously built the input's UTF-16 vector before coercing the
replacement or reading flags, and rebuilt a new string even when exec returned
null. The input is immutable; its internal length/units have no observable effects.
Materialization now waits until matching succeeds. A no-match result shares the
original input after all required replacement coercion, flags/exec accesses and
lastIndex writes. Matched replacements use the existing owning unit cache.

The local ECMA-262 snapshot e28783d5fc9dc12b3de905961e2c71410b38a202,
/big/web-standards/repositories/tc39/ecma262/spec.html:39817, was consulted.
Official clause: https://tc39.es/ecma262/#sec-regexp.prototype-%symbol.replace%.
The final empty-list case returns the original subject's full substring. This
is the consulted snapshot, not a verified current upstream revision.

Two new regressions cover ordered coercion/flags/exec effects, receiver snapshots,
functional replacement suppression, read-only lastIndex, thrown getters, legacy
statics and immutable aliases. They run in interpreter, bytecode and JIT modes.
All 39 selected regexp and nine string tests pass; strict all-target Clippy passes.
