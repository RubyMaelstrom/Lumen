Djot's actual parser repeatedly takes prefixes of its document and extracts
captures. A diagnostic profile attributed 0.406 of 1.022 sampled CPU seconds
to memcpy and 0.154 to jstr::from_units. These samples identify repeated string
work; overlapping profiles are not acceptance timings or additive speedup claims.

The established Unicode substring path rebuilt UTF-16 ranges into a Rust String,
then copied them into LStr. The new path lazily indexes non-ASCII boundaries in
the existing owning string-unit cache and copies complete UTF-8 ranges directly.
ASCII runs require no index entries. Whole-source ranges can share the immutable
source; other results own independent storage. LStr's native layout is unchanged.

The cache retains its 64-entry and 16 MiB limits, charges index storage, and
pins string identity. Short or uncacheable sources, coercion-driven eviction,
index-budget exhaustion, surrogate splits and smuggled surrogate pairs retain
code-unit reconstruction. The memory census visits each index payload once.
Index construction is cold; the shared Unicode helper is emitted out of line.
