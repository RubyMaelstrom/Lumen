CLDR number text validation — 6 October 2026
==========================================

Validate the generated NumberFormat text directory at compile time instead
of repeating string-range checks at every runtime access. The warmed formatting
fixture takes about 0.9% less time than the compact-Intl baseline. This repair
reduces the earlier table-compaction cost; it is not a broad engine speedup.

All 11132 offset/length pairs are checked for addition overflow, blob bounds
and UTF-8 boundaries. include_str! validates the blob's encoding. The runtime
ID array lookup remains bounds-checked, and one shared static directory
supplies a documented unchecked string slice. The generator emits the same
proof. IDs, all reference pairs and the 260533-byte blob are unchanged. No
runtime cache or allocation is added, and no author-visible option is assumed
immutable. These are constant-time boundary checks, not a string search.

Measured repair and limits
--------------------------

Native ARM64 Linux 7.2.7-crystal, CPU 5, Rust 1.99.0 b940084d7 / LLVM 23.1.1.
Release opt-level 3, fat LTO, one codegen unit, panic=abort, default intl + embed;
ordinary JIT and uninstrumented acceptance timings. Six balanced fresh-process
pairs per application/control and sixty startup pairs; paired 10000-resample
95% bootstrap intervals. Outputs matched and no owned builds, tests or profilers
overlapped the timing windows. Ratios below are candidate/baseline; wall time
means wait4 direct-child time, separately from Python/taskset/helper overhead.

[.983585, .996842]. Other application/control primary timers stay near parity.

A separate twelve-pair comparison directly against the date-only baseline
tests the earlier NumberFormat regression. Warm wall time is 1.007886
[1.001900, 1.010852], and user CPU is 1.007892 [1.002731, 1.012022]. That is
